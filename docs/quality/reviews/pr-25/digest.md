# PR #25 · Redact secrets from logs and events, retry failed Sentry init

## Like you are five
corpus-landing is the public early-access page for Corpus, an Android-first language-learning product. Anyone can visit it, read what the product is, and leave an email address to be told when it launches. They confirm that address by clicking a link in a mail, and they can later use a second opaque link to change their mind and leave. There are no accounts and no passwords: the links themselves are the only key. One day the site sends a single launch mail to everyone who stayed, and then it turns into a plain 'Get Corpus' page. It is built with Next.js on Vercel, keeps its list in a Postgres database at Neon, and sends its mail through Resend. The code is arranged so the rules of the product sit in the middle and never reach out to any outside service directly; the parts that talk to the database, the mail provider and the error tracker are plugged in around the edge. The repository is public, so its history and its documents are part of what it ships.

An earlier change gave the running site a way to tell its operators when something breaks, by sending error reports to a service called Sentry. The review of that change ended with thirty-one smaller problems written down but left unfixed. This change closes twenty-nine of them; two turned out to need no work. Most of the fixes are about what must never leave the machine. Reports are now cleaned in more places and more thoroughly: browser timing reports, the extra fields attached to log lines, anything buried too deep to inspect, database addresses including the host name, and the question-mark and hash parts of every web address that shows up in a report or a stack trace. The cleaning was also made fast, because one of the old text rules took whole seconds on a long line, and made careful enough not to mangle innocent text such as a colour code or a button name. The rest of the fixes make failures visible instead of silent: a failed start-up now tries once more thirty seconds later, a reporting failure can no longer break the visitor's request, the stand-in reporter writes one line to the log instead of throwing everything away, and a local test run no longer forwards real browser reports to the live service. There are also new tests for the two error pages, for the forwarding route, and for the list of values that must never be logged, and the coverage thresholds were raised to match what is now actually measured.

The four helpers read the six repairs and wrote down eleven more things. Nine are small. Two are big enough that you have to decide about them.

The first is an apostrophe. The repair to the address-hiding rule works: an address is now hidden completely however long it is, and one helper checked that by running the new rule against about a million made-up inputs without finding a single case where it hides less than it ought to. But the list of characters the rule treats as part of an address leaves out the apostrophe, and the sign-up form accepts one. A helper tried every single character the form allows, one at a time, and the apostrophe is the only one the form takes and the rule does not know about. For somebody whose address contains one, everything in front of it is sent out readable, which in practice is their whole name. The repair is one character long.

The second is about the little door that passes browser reports along. The repair made it write a line when it cannot read what a browser sent, which is what we asked for. But the line does not say what went wrong. A visitor closing their tab half-way and the server's own machinery breaking now produce exactly the same line, at a level nobody is watching. So the thing the repair existed to make visible is still hidden, now behind the ordinary case instead of behind nothing.

Two of the nine small ones are worth knowing about even though the gate set them aside. One of the tests written to prove the first repair works passes just as happily against the unrepaired code, so it does not earn its name; the repair is still properly proven, by the test sitting next to it. And the new warning line about deliberately dropped reports will also show up during an ordinary local speed test, even though the note written directly above it promises it never does.

This is the last round. Once you answer, the gate freezes: whatever you leave for later stays written down in the ledger, and nothing further gets reviewed before this is merged.

What you need to decide: for each of the two, fix it now or leave it for later.
